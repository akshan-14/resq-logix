# Priority Intelligence Engine

This module answers the critical disaster management question: *"How urgent is this location/request, and which requests should be handled first?"*

It uses a Machine Learning pipeline to evaluate demographic data, emergency requests (SOS), supply shortages, and environmental access to generate a priority score and classification.

## 1. Problem Being Solved
During a disaster in the North Eastern Region, logistics commanders face simultaneous requests for aid. The Priority Intelligence Engine ingests real-time data to triage these requests autonomously, allowing commanders to deploy limited resources (vehicles, helicopters, supplies) to the areas of most critical need first.

## 2. Synthetic Data Disclaimer
**IMPORTANT:** The ML models are trained on **synthetic prototype data** (`ai/data/priority_training.csv`). 
- This data uses complex non-linear relationships to mimic reality (e.g., compounding medical emergencies with low medicine).
- It is designed strictly for hackathon demonstrations.
- The model must be retrained on real historical operational data before production deployment.

## 3. Dataset Schema
- **Features (Inputs)**: `population`, `population_density`, `vulnerable_population`, `sos_count`, `medical_emergency_count`, `injured_people`, `food_supply_days_remaining`, `water_supply_days_remaining`, `medicine_supply_days_remaining`, `shelter_demand`, `distance_to_nearest_hospital_km`, `distance_to_nearest_warehouse_km`, `accessibility_score`, `accessibility_risk`, `rainfall_mm`, `flood_risk`, `landslide_risk`, `weather_severity`, `road_blockage`, `connectivity`, `disaster_severity`, `request_age_hours`.
- **Target Variables**:
  - `priority_score` (Regression: 0-100)
  - `priority_level` (Classification: LOW, MEDIUM, HIGH, CRITICAL)

## 4. Evaluation Methodology & Selected Model
The training pipeline (`train_priority_model.py`) splits the data into 80% training / 20% validation.
It evaluates `RandomForestClassifier` against `GradientBoostingClassifier` using Weighted F1-score as the primary selection metric.
The better performing model is saved as the production classifier, while a `RandomForestRegressor` handles the numerical 0-100 score.

## 5. Inference & Explainability
The inference class extracts `feature_importances_` from the trained Random Forest model. 
When predicting urgency, the system returns the top factors (e.g., `Medicine Supply Days Remaining`, `Medical Emergency Count`). 
*Note: Feature importance indicates model influence and does not strictly prove causation.*

## 6. Operational Safeguards
The ML model predicts based on learned statistical patterns. However, disaster management requires hard logical fail-safes. The engine includes operational overrides that force a `CRITICAL` state regardless of ML output:
- **CRITICAL SHORTAGE**: High medical emergencies (>=15) with extremely low medicine (<= 2 days).
- **ISOLATION STARVATION RISK**: High road blockage (>=9) with extremely low food (<= 1 day).

## 7. Phase 4 Integration
This module is fully decoupled but designed to integrate with the Phase 4 Accessibility Engine. 
The Accessibility Score generated by Phase 4 can be fed directly into this Priority model to adjust urgency (e.g., highly isolated populations running out of food see an exponential spike in priority).

## 8. Future Real-Data Integration
For production, the synthetic dataset will be replaced by a live data ingestion pipeline:
```
REAL DATA (SOS records + historical disaster events + population data + resource consumption + weather)
    ↓
DATA CLEANING & FEATURE ENGINEERING
    ↓
TRAINING & VALIDATION
    ↓
PRIORITY MODEL PREDICTION
    ↓
LOGISTICS DECISION ENGINE
```

## 9. Limitations
- Does not currently perform route optimization.
- Does not assign vehicles or dispatch resources (This is handled by the Logistics Management Module).
