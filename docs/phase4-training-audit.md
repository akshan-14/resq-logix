# Phase 4 & 5 Training Data Audit

Since we have moved to real-world live data (Open-Meteo, OSRM, Nominatim, Logistics DB) for inference, the ML models (`predict_accessibility.py` and `decision_engine.py`) must be retrained.

## The Issue
Currently, Phase 4 and Phase 5 models are trained on completely synthetic distributions generated by `generate_synthetic_data.py` and `generate_priority_data.py`. The ML model essentially learned a non-linear algebraic equation (a synthetic fitness function) rather than physical real-world patterns.

If we feed REAL data (e.g., population = 11,000,000) into a model that expects synthetic data (population = 0-10), the model will produce garbage or completely fail its constraints.

## Next Steps for Retraining
Before we remove the synthetic generators completely, we must:

1. **Obtain Real Historical Baselines**: Gather bulk data from data.gov.in (Census), HDX, and EM-DAT to represent real disaster scenarios (e.g., 2013 North India floods, 2018 Kerala floods).
2. **Re-scale Features**: Ensure that live features (like `population`) match the scaling (StandardScaler/MinMaxScaler) of the new training data.
3. **Train Models**: Train `RandomForestRegressor` on these historical baselines.
4. **Deploy**: Update the pickled models in `ai/models/` and only then remove the synthetic generators.

Until Retraining is complete, LIVE mode will pipe real data through the Feature Builder, but inference accuracy will be skewed by the model's synthetic assumptions.
